For FastAPI monorepos

Ship the kernel.
Leave the husk behind.

pyhusk discovers each service’s routes by importing its app, follows the imports and Depends() chains those routes reach, and builds an image containing that slice and nothing else. Then it remembers what went into each image, so you rebuild only the services that changed.

Get started View on GitHub
  1. uv tool install pyhuskPython 3.12+, isolated from your repo
  2. cd your-monorepo && pyhusk initWrites pyhusk.yaml from detected services
  3. pyhusk buildBuilds every stale service, verifies each image

How it works

Four stages, each one feeding the next. No configuration to tune, no annotations to add — the app itself is the specification.

  1. 1

    Probe the living app

    pyhusk imports each service in a subprocess and walks its routes, recording every endpoint and every callable in each route’s dependency tree — exact, not guessed.

    app.routes → endpoints + Depends() tree entry module always included
  2. 2

    Slice what the routes reach

    An AST pass follows local imports from those seeds and pins third-party packages from your lock file, transitively closed. Unparseable files are kept with a warning, never dropped.

    seeds → local files + third-party pins uvicorn added (apps never import it)
  3. 3

    Hash everything, stamp the image

    File contents, requirements, Dockerfile, and base-image digest are hashed and stamped onto the image as a label — so staleness survives fresh CI runners with empty caches.

    org.pyhusk.slice = sha256(files + reqs + dockerfile + base digest)
  4. 4

    Boot it before you trust it

    Each fresh image is started and its OpenAPI schema compared against the probed routes. Failures are untagged and removed; a missing file becomes a build error, not an outage.

    schema → healthcheck → boot failed image? removed, build retried

One slice, thirteen commands

The same import graph powers builds, linting, selective tests, and archaeology. Full reference →

build
Minimal images for stale services, verified by booting each one.
plan
Which services are stale, as text or JSON for CI matrices.
lint
Service boundaries, forbidden imports, cycles, plus ruff on shipped code.
test
Run only the tests whose import slice touches the git diff.
affected
Preview which services and tests a diff touches.
why
Shortest import path from a service to any file or package.
unused
Python files no service reaches. Candidates for deletion.
log
Commit history behind a service’s current slice.
benchmark
Pruned vs whole-repo build time and size, honestly measured.
init · list · skill · build-bases
Set up a repo, see its services, teach your agents, prebuild shared bases.

Honest limits

What pyhusk assumes today. If these don’t describe your setup, it will tell you loudly rather than guess.

uv monorepos

Pins come from uv.lock and apps run from the repo’s own .venv. Other layouts are not supported yet.

FastAPI-first

Route discovery imports FastAPI/Starlette apps. Workers and jobs slice from the entry file with no route awareness.

Docker builds images

Only build, benchmark, and --compare need a daemon. Lint, test, and tracing run anywhere.
